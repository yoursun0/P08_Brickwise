# Brickwise — Implementation Guide (Steps 1–9)

This is the working order. Steps **1–7 use no LLM**. Steps **8–9 use the official DeepSeek API only** (`deepseek-flash`, `DEEPSEEK_API_KEY`). Do not call SiliconFlow, OpenAI, or any other model.

**Job to be done:** user uploads one tabular 價單 PDF → sortable unit table → ranked shortlist CSV.

**Already done (do not redo):**
- Text-layer parser `src/lib/extract/extractPriceList.ts`
- Golden tests on `samples/芊御3號價單-114伙- 18.07.2026.pdf` (114 units, known cells)
- 攻略圖 files reject as `not_tabular`
- Inspect CLI: `bun run extract -- <pdf>` writes UTF-8 **with BOM** CSV
- Results UI exists, but on **seeded** rows only
- Magic-link login route exists

**Do not start Step 8 or 9 until a second real tabular 價單 fails (8) or you have a measured no-text-layer file you care about (9).**

---

## Conventions

- JS/TS: `bun run`, `bun add`. Python: `uv` (not needed here).
- Numbers are copied from the PDF, never generated by a model.
- Fail closed: empty text / < 10 valid rows / 攻略圖 → reject, do not fall through to vision.
- `DEEPSEEK_API_KEY` is **server-only**. Never `NEXT_PUBLIC_DEEPSEEK_API_KEY`. Never send it to the browser.
- Excel CSVs: UTF-8 with BOM (`\uFEFF`).
- Tests: `bun run test`. Parser tests stay in `src/lib/extract/extractPriceList.test.ts`.

## Step 1 — Persist extracted units (`prices` jsonb + `layout`)

**Why:** Real 價單 is not Plan A/B. 芊御 has 訂價 / A1 / B1 / B1不借二按.

**Schema** (`supabase/migrations/0002_prices_layout.sql`):
- `units.layout text`
- `units.prices jsonb not null default '[]'`  
  Shape: `[{ "key": "list", "label": "訂價", "amount": 6442900 }, ...]`
- `projects.price_columns jsonb not null default '[]'`  
  Shape: `[{ "key": "list", "label": "訂價" }, ...]`
- Relax `projects.price_basis` check: any text key **or** `'lowest'`.
- Keep legacy `price_original / price_plan_a / price_plan_b` populated as a compatibility copy of the first three columns. **Source of truth is `prices`.**

**Code:**
- `src/lib/types.ts` — `Unit.prices`, `Unit.layout`, `PriceBasis` = `string`
- `src/lib/price.ts` — `computePrice(unit, basis)` reads `prices[]`; if empty, fall back to legacy columns (keep existing tests green)
- Update `supabase/seed.sql` so demo rows have `prices` arrays

**Exit:** `bun run test` still passes. A unit round-trip can store 4 named amounts.

**No LLM.**

## Step 2 — Compute tags in code

**Why:** Results filters (`剔除不划算高層`, `剔除地下/最低層`) must work on extracted files, not only seed SQL.

**Rules (deterministic, in `src/lib/price.ts`):**
- Stack = same `tower` + `unit_no`
- Adjacent = consecutive listed floors in that stack (sorted by `floor_sort_key`)
- `不划算高層` if `(price[higher] - price[lower]) / price[lower] >= 0.10` — tag the **higher** floor
- `最低層` = units with the global min `floor_sort_key`
- `地下` if `floor_raw` matches `G/F`, `GF`, `地下`, `地面`
- Recompute when the user switches price basis (no re-parse, no credits)
- Persist tags at analyze time using the default basis `lowest`; the Results page always recomputes for the active basis

**Tests:** a 3-floor stack with +20% on the top floor is tagged; G/F is `ground_floor` + `lowest_floor`.

**No LLM.**

## Step 3 — Upload → parse → Results

**Why:** this is the product. The parser is useless if the website still shows 10 demo rows.

**Flow:**
1. Logged-in user, existing or new project
2. Drop **one** PDF on `/projects/[id]/upload`
3. `POST /api/projects/[id]/analyze` with the file (Node runtime, `unpdf` server-side)
4. Hash SHA-256, page count, run `extractPriceList`
5. On success: replace that project’s units, set `price_columns`, redirect to `/projects/[id]/results`
6. On reject (`not_tabular` / `no_text` / `too_few_units` / `too_many_pages`): show the Chinese message, **do not** invent rows, **do not** call DeepSeek

**Caps:** PDF only. Max 10 pages (already in the parser). Max ~20 MB.

**Exit:** locally upload `samples/芊御3號價單-114伙- 18.07.2026.pdf` and see **114 real rows** on Results. Upload a 攻略圖 and see the reject message.

**No LLM.** `next.config.ts` must mark `unpdf` as a server external package.

## Step 6 — Login, save, hash cache

**Why:** so a second visit does not re-parse and does not re-charge.

- Keep Email magic link (`/login` → `/auth/callback` → `/dashboard`)
- On first authenticated request, upsert `profiles` (id, email, `credits_balance = 3`, `free_credit_month = YYYY-MM` Hong Kong time)
- Dashboard: **新增 project** actually inserts a row and goes to upload
- Same **user** + same **file_hash** + previous `succeeded` document: copy stored units into the current project, skip parse, skip credit deduction
- One PDF per project for v1: re-analyze replaces units

**Exit:** upload 芊御 twice (same account) → second time is instant, credits unchanged.

**No LLM.**

## Step 7 — Usage caps without Stripe

**Why:** stop unbounded CPU/parse spam. Billing UI is later.

| Rule | Value |
|---|---|
| Monthly grant | +3 credits on first analyze of a new `YYYY-MM` (Asia/Hong_Kong) |
| PDF credits | `max(1, ceil(page_count / 5))` |
| Charge when | first **successful** parse of a new hash |
| Do not charge | reject, parse failure, hash cache hit |
| Insufficient | HTTP 402, show 「credits 不足」, do not parse |
| Page cap | 10 (parser already rejects) |

Show remaining credits in the top bar when logged in. Leave `/pricing` as a stub (“稍後推出”). Do not add Stripe.

**Exit:** a user with 0 credits is blocked before parse. A 3-page PDF costs 1 credit on first success.

**No LLM.**

## Step 8 — Header-mapping LLM (only if a second tabular 價單 fails)

**When:** the regex parser returns `not_tabular` **but** the file is clearly a table (has 座/樓/室/實用 and many `$` amounts). Not for 攻略圖. Not for scans.

**Model:** official DeepSeek API.

| Param | Value |
|---|---|
| Base URL | `https://api.deepseek.com` |
| Path | `POST /chat/completions` |
| Auth | `Authorization: Bearer ${DEEPSEEK_API_KEY}` |
| `model` | `deepseek-flash` |
| `thinking` | `{ "type": "disabled" }` — mapping does not need reasoning |
| `response_format` | `{ "type": "json_object" }` |
| `max_tokens` | `800` |
| Timeout | 20s |
| Calls | **at most 1 per document** |

Send **headers + 3 sample rows of raw text only**. Never send all 114 unit rows. Never ask the model for prices; the parser copies numbers after columns are named.

Expected JSON:

```json
{
  "columns": [
    { "index": 0, "key": "tower", "label": "座" },
    { "index": 5, "key": "list", "label": "訂價" },
    { "index": 6, "key": "a1", "label": "A1 現金付款計劃" }
  ]
}
```

Validate: every `key` in an allow-list; amounts still parsed with regex. If JSON is invalid or amounts fail regex → same reject as today. Do not retry with a bigger prompt.

Wire behind a server flag `HEADER_MAP_LLM=1` default **off** until you have a failing second 價單.

**Do not implement in the 1–7 pass.**

## Step 9 — Vision for 攻略圖 / scans (later, different extractor)

**When:** a file you care about has no usable text layer, **and** steps 1–7 already work on tabular 價單.

Still official DeepSeek, still `deepseek-flash` (native vision).

| Param | Value |
|---|---|
| Base URL | `https://api.deepseek.com` |
| Path | `POST /chat/completions` |
| Auth | `Authorization: Bearer ${DEEPSEEK_API_KEY}` |
| `model` | `deepseek-flash` |
| Image | `content[]` part `{ "type": "image_url", "image_url": { "url": "data:image/png;base64,..." } }` |
| `thinking` | `{ "type": "disabled" }` unless a single page fails structured OCR |
| `max_tokens` | keep bounded; prefer JSON |

Rules that do not change:
- Render **one page at a time**, table region if you can crop
- Ask for a JSON array of units; **every amount must still match `/[\d,]+/` on the page text/OCR**
- If a digit cannot be checked, drop that unit or fail the page — do not keep a hallucinated price
- Do not rank flats with the model
- Do not mix this pipeline into the tabular parser
- Cache by file hash so the same 攻略圖 is never billed twice

**Do not implement in the 1–7 pass.**

## DeepSeek client (when you reach 8/9)

Server-only helper, e.g. `src/lib/llm/deepseek.ts`:

```ts
const res = await fetch("https://api.deepseek.com/chat/completions", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
    Authorization: `Bearer ${process.env.DEEPSEEK_API_KEY}`,
  },
  body: JSON.stringify({
    model: "deepseek-flash",
    thinking: { type: "disabled" },
    response_format: { type: "json_object" },
    max_tokens: 800,
    messages: [
      { role: "system", content: "Return JSON only. Copy numbers, never invent them." },
      { role: "user", content: prompt },
    ],
  }),
});
```

Vision variant: user `content` is an array of `{ type: "text", text }` + `{ type: "image_url", image_url: { url: dataUrl } }`.

If `DEEPSEEK_API_KEY` is missing, Step 8/9 must no-op and keep the deterministic reject. Do not crash the analyze path.
